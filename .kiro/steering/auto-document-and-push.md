# 自动文档、变更记录与推送流程

对本项目进行任何代码、配置或文档修改时，默认执行以下完整流程：

1. 完成用户要求的修改，并运行与改动最相关的构建、检查或冒烟验证。
2. 如果功能、使用方法、部署方式、接口、数据结构或排版行为发生变化，同步更新 `README.md`。
3. 在 `CHANGELOG.md` 当前日期下记录本次修改，使用“新增 / 变更 / 修复 / 文档 / 运维”等清晰分类；描述用户可感知的结果和重要技术约束，避免只写文件名。
4. 执行 `git diff --check`，确认只包含预期文件，不提交 `node_modules`、`frontend/dist`、SQLite 数据库、密钥或其他本地产物。
5. 使用清晰的 Conventional Commit 风格提交信息创建新提交，不修改或覆盖既有提交。
6. 将当前分支推送到已配置的远程仓库；新分支使用 `git push -u`，禁止强制推送。
7. 推送后确认本地提交与远程分支一致，并向用户报告提交哈希、验证结果和仓库地址。

用户已明确授权本项目在每次修改完成后自动更新文档、记录变更并推送，因此无需重复询问是否提交或推送。

以下情况不得自动推送：

- 用户在当前请求中明确要求不要提交或不要推送。
- 构建或关键验证失败且尚未修复。
- 改动疑似包含密钥、个人敏感信息、数据库文件或非预期生成物。
- 推送需要强制更新、会覆盖远程历史，或远程分支存在尚未处理的冲突。

遇到上述情况时应停止提交或推送，保留本地改动并明确说明阻塞原因。
